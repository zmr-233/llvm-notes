# 05 函数调用

一个函数调用另一个函数时，双方各做了什么：call、ret 怎么跳，栈怎么用，寄存器由谁保存，
参数和返回值放在哪，序言和尾声为什么是那几条指令。

本篇讲这些的共同基础。riscv-registers 的 [03-calls.md](../riscv-registers/03-calls.md) 在这个基础上讲各种变化：
-msave-restore 与 Zcmp 的字节数、帧指针、gp、tp、中断处理函数。

## 1. 前提词

- 调用者（caller）、被调用者（callee）：keep 里调用 g，keep 是调用者，g 是被调用者。同一个函数
  对上一层是被调用者，对下一层是调用者。
- 调用约定（calling convention）：调用者和被调用者事先说好的规则。RISC-V 的在 psABI 的
  `riscv-cc.adoc` 里（版本见 README）。下文 `riscv-cc.adoc:行号` 指它。
- 叶函数：不调用任何函数的函数。
- 栈帧：一个函数在栈上占的那一块内存（第 3 节）。
- 序言（prologue）、尾声（epilogue）：编译器在函数开头、结尾插入的几条指令，负责开栈帧、存取寄存器
  （第 6 节）。

为什么需要约定：keep 和 g 可以写在两个 .c 文件里分别编译，g 甚至可以在一个库里。编译 keep 时看不到
g 的代码，只能按约定假设 g 的行为。约定规定参数放哪、结果放哪、从哪里回来、调用之后哪些寄存器
还是原值、栈怎么用。硬件只提供 jal、jalr 两条跳转，其余都是约定。

## 2. call 与 ret：只有一个 ra

```
call f   即 jal ra, f          ra ← call 下一条指令的地址 ；pc ← f
ret      即 jalr zero, 0(ra)   pc ← ra
```

- RISC-V 没有专门的调用、返回指令，call、ret 都是伪指令。
- 目标文件里的 call 是 `auipc ra` 加 `jalr ra`，链接器够得着时再改成 `jal ra`（04 第 4 节）。无论哪种写法，
  效果都是上面这一行：ra 得到返回地址，pc 跳到 f。
- 实验 `ex/frame.c` cell 2 反汇编出了真实指令：ret 是 `jalr zero, 0x0(ra)`，call g 是
  `auipc ra, 0x0 ; jalr ra, 0x0(ra)`。

ra 只有一个。keep 调用 g 时，call g 把新的返回地址写进 ra，keep 自己的返回地址就被覆盖了。所以：

- 一个函数只要还要调用别的函数，就得在调用前把自己的 ra 存起来，返回前再取回。序言存 ra，理由只有这一条。
- 叶函数的 ra 从头到尾没被改过，不用存。

## 3. 栈

ra 要存到内存里。存在哪，由两件事决定：

- 每一次调用都要有自己的一块内存。递归时，同一个函数有好几次调用都还没结束，各自要存各自的 ra，
  不能共用一个固定地址。
- 调用总是后开始的先结束，所以按栈的方式分配：开空间时从一端往外扩，还空间时从同一端收回。

RISC-V 的做法（`riscv-cc.adoc:187` 起）：

- sp（x2）指向栈顶，栈往低地址长。开 16 字节是 `addi sp, sp, -16`，还回去是 `addi sp, sp, 16`。
- 一个函数开出的这一块就是它的栈帧。开之前 sp 指向调用者栈帧的底部，所以各层的栈帧从高地址往低
  地址依次排列。
- 进入函数时 sp 必须是 16 的倍数（ilp32e 是 4，:285）。函数执行期间也要保持对齐（:193）。
- sp 下方的内存随时可能被别的代码写掉，不能把数据放在那里（:203–204）。例如中断处理程序可以借用
  被打断代码的栈（:197–198）。

## 4. 两种保存责任

所有函数共用同一组寄存器。keep 调用 g，g 会改哪些寄存器，keep 看不到。约定把寄存器分成两类，
见 `riscv-cc.adoc:10` 起的表，最后一列是「调用之后是否保持原值」：

- 不保持：ra、t0–t6、a0–a7。
  - 被调用者可以随便改。
  - 调用者如果有值要在调用之后继续用，要么不放在这些寄存器里，要么自己在调用前存起来。
  - 这叫调用者保存（caller-saved）。
- 保持：sp、s0–s11。
  - 被调用者想用它们，就必须在序言里存下旧值，在尾声里恢复（:95–96）。
  - 这叫被调用者保存（callee-saved）。
- zero、gp、tp 不参与：zero 恒为 0，gp、tp 不应被函数修改（:27–28）。

为什么两类都要有：

- 如果全是调用者保存，一个值每跨过一次调用，就要存、取一次。
- 如果全是被调用者保存，最简单的叶函数用一个寄存器也得先存。
- 分成两类以后，叶函数只用 t、a，一次存取都没有；要跨过调用的值放进 s，序言存一次、尾声取一次，
  中间调用多少次都不用再存。

ra 算在「不保持」里，只是说调用之后 ra 不再是原值。这是必然的，因为 call 本身就写 ra。各寄存器的
编号和名字见 riscv-registers 的 02 第 2 节。

## 5. 参数与返回值

规则（`riscv-cc.adoc:103` 起的整数调用约定）：

- 参数寄存器是 a0–a7 共 8 个，其中 a0、a1 也用来放返回值（:105–106）。
- 不超过 XLEN 位的标量占一个寄存器，寄存器用完了就放在栈上（:108–109）。XLEN 是整数寄存器的位数，
  RV32 是 32，RV64 是 64。比 XLEN 窄的整数先按类型的符号扩展到 32 位，再符号扩展到 XLEN 位（:110–112）。
- 2×XLEN 位的标量占两个寄存器，低位在编号小的那个（:116–121）。更宽的传地址（:123–124）。
- 结构体不超过 2×XLEN 位的，按内存里的布局放进一个或两个寄存器；更大的传地址（:126–141）。
- 栈上的参数由调用者放好，被调用者进入时第一个在 0(sp)，后面的依次往高地址排（:189–190）。
- 返回值按「同类型的第一个参数」的方式返回（:178）。第一个参数最多占 a0、a1 两个，所以返回值也
  最多用 a0、a1。要传地址的那种返回值，由调用者先准备好内存，把地址当作隐含的第一个参数放进 a0
  （:179–181）。

所以返回寄存器有两个，是为了让 2×XLEN 以内的值不经过内存就能返回，例如 RV32 上的 64 位整数、
两个 int 组成的结构体。

实验 `ex/ret.c`，`-Os`：

```
                          RV32（2×XLEN = 8 字节）             RV64（2×XLEN = 16 字节）
r64   返回 long long      a0 低 32 位、a1 高 32 位           a0
r2    返回 8 字节结构体    a0、a1，函数体只剩 ret              a0 一个寄存器，a、b 拼在一起
r3    返回 12 字节结构体   a0 是调用者给的地址，a、b、c 顺延    a0 放 a、b，a1 放 c
                          到 a1–a3，sw 三次写进去
call3 取 use3() 的 c      mv a0, sp ; call use3 ; lw a0, 8(sp)  call use3 ; sext.w a0, a1
take9 第 9 个参数          lw a1, 0(sp)                        ld a1, 0(sp)
```

- 同一个 12 字节的结构体，RV32 上超过 2×XLEN，走内存；RV64 上不超过，放在两个寄存器里。
- call3 在 RV32 上是调用者一方的做法：在自己的栈帧里留出 12 字节，把地址放进 a0 再调用。
- take9 的第 9 个参数：调用者 call9 把它写在自己栈帧的 0(sp)，take9 进入时它就在 0(sp)。

## 6. 序言与尾声

序言、尾声就是把第 2–4 节落实成指令。实验 `ex/frame.c` cell 1 的 keep（`-march=rv32im -Os`）：

```
int g(int);
int keep(int x) { return g(x) + x; }

keep:  addi sp, sp, -16      序言  开 16 字节栈帧
       sw   ra, 12(sp)       序言  存返回地址：下面的 call g 会覆盖 ra
       sw   s0, 8(sp)        序言  存 s0 的旧值：下面要用 s0
       mv   s0, a0                 x 在 call g 之后还要用，而 g 会改 a0，所以挪进 s0
       call g                      x 已经在 a0，正好是 g 的第一个参数
       add  a0, a0, s0             g 的结果在 a0，加上 x，留在 a0 作返回值
       lw   ra, 12(sp)       尾声  取回返回地址
       lw   s0, 8(sp)        尾声  恢复调用者的 s0
       addi sp, sp, 16       尾声  还栈
       ret                   尾声
```

下面按每条指令的定义手算一遍，地址和数值是假设的。设 main 调用 keep(5) 之前：

- sp = 0x1000；
- main 自己在 s0 里放着 0x77；
- main 里 `call keep` 的下一条指令地址记作 R1；
- keep 里 `call g` 的下一条指令地址记作 R2。

```
刚进 keep       ra=R1   sp=0x1000   s0=0x77   a0=5
序言之后        sp=0xff0   内存[0xffc]=R1   内存[0xff8]=0x77
mv 之后         s0=5
call g 之后     ra=R2。寄存器里的 R1 没了，内存 0xffc 里还有
g 返回到 R2     a0=g(5)。sp 仍是 0xff0，s0 仍是 5，这两个由 g 按约定保住；ra 和其他 t、a 不再可靠
add 之后        a0=g(5)+5
尾声之后        ra=R1   s0=0x77   sp=0x1000
ret             pc=R1，回到 main
```

main 看到的是：sp、s0 和调用前一样，a0 里是结果。第 4 节的约定要求的就是这些。

keep 的栈帧：

```
0x1000   进入 keep 时 sp 指向这里，再往上是 main 的栈帧
0xffc    R1，keep 的返回地址
0xff8    0x77，main 的 s0
0xff4    空，凑满 16 字节
0xff0    空，序言之后 sp 指向这里
```

序言存哪些寄存器，由函数自己决定：函数体里改了哪个被调用者保存寄存器就存哪个，有调用就存 ra。
keep 用了 s0，有调用，所以存 s0、ra。

## 7. 叶函数与尾调用

同在 `ex/frame.c` cell 1：

```
leaf:  slli a2, a0, 1 ; add a0, a0, a1 ; add a0, a2, a0 ; ret
tail:  addi a0, a0, 1 ; tail g
```

- leaf 是叶函数：没有调用，ra 不会被覆盖；只用 a0–a2，也不用存 s。于是没有序言和尾声。
- tail 的源码是 `return g(x + 1);`，最后一件事是调用 g 并直接返回它的结果。这叫尾调用，编译器不再
  call g 然后 ret，而是直接跳到 g：
  - 跳之前，本来尾声要做的事先做完：取回 ra，恢复 s，还栈。tail 什么都没存，这一步是空的。
  - 跳转用不写返回地址的 jalr。ra 里还是 tail 的调用者给的返回地址，g 执行 ret 时直接回到那里。
  - `tail g` 在目标文件里是 `auipc t1, 0x0 ; jalr zero, 0x0(t1)`（cell 2）。暂存地址不能用 ra，因为 ra
    里的返回地址要留给 g，所以借 t1（04 第 4 节）。
- 通过函数指针做尾调用时，指针放在哪个寄存器还受处理器返回地址预测的限制，见 06。

## 8. LLVM 里的对应

llvmorg-21.1.8。LLVM 把一个函数翻成机器指令时，函数入口、调用、返回这三处先按调用约定展开成普通的
寄存器拷贝和栈存取，这一步叫 lowering（下降），由每个后端自己实现。

- `RISCV/RISCVCallingConv.cpp:325` 的 CC_RISCV：决定每个参数、返回值放进哪个寄存器或哪个栈槽，
  即第 5 节的规则。
- `RISCV/RISCVISelLowering.cpp`：
  - LowerFormalArguments（:22226）：函数入口，从寄存器和栈上取出参数；
  - LowerCall（:22495）：调用方把参数放好，发出调用；
  - LowerReturn（:22832）：把返回值放进 a0、a1。
- `RISCV/RISCVCallingConv.td:16–19`：被调用者保存列表，是 ra、s0–s11。sp 不在列表里，由序言、尾声
  单独处理；ra 在列表里的原因见 riscv-registers 的 03 第 3 节。
- `RISCV/RISCVFrameLowering.cpp:896` 的 emitPrologue、:1180 的 emitEpilogue：生成序言和尾声，
  按函数实际改了哪些列表里的寄存器决定存哪些。
