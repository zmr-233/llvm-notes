# 01 指令的编码

## 1. 前提词

- 编码：一条指令在内存里的二进制值。汇编器把 `add a0, a1, a2` 翻成 0x00c58533，处理器取到这
  32 位，再按同样的规则拆开执行。
- 字段：编码里固定的几位，表示一项内容。
- opcode：最低 7 位，指令的大类。funct3（第 14–12 位）、funct7（第 31–25 位）在同一大类里再细分，
  例如 add 和 sub 的 opcode、funct3 相同，funct7 不同。
- rd、rs1、rs2：目的寄存器和两个源寄存器的编号，各 5 位，能表示 x0–x31。
- 立即数（immediate）：直接写在指令编码里的常数，例如 `addi a0, a1, -1` 的 -1。
- 符号扩展：把一个 n 位的有符号数扩成更宽的数，高出来的位全部填成它的最高位（符号位）。
  12 位的 0xfff 符号扩展成 32 位是 0xffffffff，即 -1。零扩展则是高位全填 0。
- 位的写法：`[31:25]` 表示第 31 位到第 25 位，第 0 位是最低位。`imm[12]` 表示立即数的第 12 位，
  `imm[10:5]` 表示立即数的第 10 位到第 5 位。

## 2. 指令长度

- 基础指令集的指令都是 32 位，编码的最低两位是 11。C 扩展的 16 位压缩指令，最低两位是 00、01
  或 10（`intro.adoc:472` 起）。处理器取到指令的前 16 位，看最低两位就知道这条指令有多长。
- 没有 C 扩展时，指令必须 4 字节对齐；有 C 时 2 字节对齐即可，32 位指令也可以从任意 2 字节边界
  开始（`rv32.adoc:137` 起）。
- 本篇只讲 32 位格式。16 位格式在 riscv-registers 的 02 第 3、4 节讲过。

## 3. 六种格式

```
         [31:25]      [24:20]  [19:15]  [14:12]  [11:7]         [6:0]
R 型     funct7       rs2      rs1      funct3   rd             opcode   add、sub、slt
I 型     imm[11:0]             rs1      funct3   rd             opcode   addi、lw、jalr
S 型     imm[11:5]    rs2      rs1      funct3   imm[4:0]       opcode   sw、sb
B 型     imm[12|10:5] rs2      rs1      funct3   imm[4:1|11]    opcode   beq、blt
U 型     imm[31:12]                              rd             opcode   lui、auipc
J 型     imm[20|10:1|11|19:12]                   rd             opcode   jal
```

- 第一行是各字段在 R 型里占的位。I 型的 imm[11:0] 占第 31–20 位；U 型、J 型的立即数占第 31–12 位。
- 读法：B 型的 `imm[12|10:5]` 表示第 31–25 位依次放 imm[12] 和 imm[10:5]；`imm[4:1|11]` 表示
  第 11–7 位依次放 imm[4:1] 和 imm[11]。J 型的 `imm[20|10:1|11|19:12]` 同理。
- 格式的图在 `rv32.adoc:134` 起的「Base Instruction Formats」一节和 :196 起的「Immediate Encoding
  Variants」一节。LLVM 里每种格式是一个 TableGen 类，`RISCV/RISCVInstrFormats.td` 的 RVInstR（:354）、
  RVInstI（:434）、RVInstS（:467）、RVInstB（:482）、RVInstU（:499）、RVInstJ（:510）。第 4 节按这张图
  拆实验里的编码，拆出来的值和 objdump 打印的一致。

这样排有几个用意，`rv32.adoc:165` 起的正文和 :179 起的注释写明了：

- rs1、rs2、rd 在所有格式里位置不变。取寄存器编号是处理器译码的关键路径，这样不用先判断格式就能取。
  代价是立即数的各位在不同格式里位置不同。
- 除了 CSR 指令里的 5 位立即数，立即数一律符号扩展，而且符号位总在第 31 位，符号扩展的电路不用等
  格式判断。
- 普通指令的立即数只有 12 位，另设一条带 20 位立即数的 lui 来装高位（02）。这样普通指令留下更多
  编码空间。

## 4. 手工拆几条

实验 `ex/formats.s`（`-march=rv32i`）。下面每条先写编码，再按字段拆开，从高位到低位。

R 型，`add a0, a1, a2` = 0x00c58533：

```
0000000 01100 01011 000 01010 0110011
funct7  rs2   rs1   f3  rd    opcode
        x12   x11       x10
```

I 型，`addi a0, a1, -1` = 0xfff58513：

```
111111111111 01011 000 01010 0010011
imm[11:0]    rs1   f3  rd    opcode
```

imm = 0xfff，符号扩展后是 -1。

S 型，`sw a0, 8(sp)` = 0x00a12423：

```
0000000   01010 00010 010 01000    0100011
imm[11:5] rs2   rs1   f3  imm[4:0] opcode
          x10   x2
```

imm = 0000000 拼 01000 = 8。存储指令没有 rd，原来 rd 的位置放立即数的低 5 位。

B 型，`beq a0, a1, L` = 0xfeb508e3。beq 在偏移 0x10，L 在偏移 0：

```
1       111111    01011 01010 000 1000     1       1100011
imm[12] imm[10:5] rs2   rs1   f3  imm[4:1] imm[11] opcode
```

按 imm[12]、imm[11]、imm[10:5]、imm[4:1] 的顺序拼起来，最低位补 0：

```
1 1 111111 1000 0 = 0b1111111110000（13 位）= -16
```

目标 = beq 自己的地址 0x10 + (-16) = 0，就是 L。

J 型，`jal ra, L` = 0xfe5ff0ef。jal 在偏移 0x1c：

```
1       1111110010 1       11111111   00001 1101111
imm[20] imm[10:1]  imm[11] imm[19:12] rd    opcode
```

```
imm[20] imm[19:12] imm[11] imm[10:1]  补 0
1       11111111   1       1111110010 0     = 21 位的 -28
```

目标 = 0x1c - 28 = 0。

U 型，`lui a0, 0x12345` = 0x12345537：高 20 位就是 0x12345，rd 是 01010（x10）。

## 5. 分支和跳转的立即数为什么打乱

- B 型和 S 型只有一处不同：B 型的立即数表示 2 的倍数的偏移，最低位总是 0，不用存。
  硬件没有把整个立即数左移一位，而是让 imm[10:5] 和符号位留在 S 型的原位，把 S 型存最低位的
  第 7 位拿来放 imm[11]（`rv32.adoc:206` 起）。
- J 型和 U 型的关系相同：同样 20 位的立即数，U 型左移 12 位使用，J 型左移 1 位使用，各位尽量放在
  相同的位置（`rv32.adoc:213` 起）。
- `rv32.adoc:238` 起的注释说明了原因：在最简单的实现里，同一个立即数位在各种格式中尽量来自编码的
  同一位，比用多路选择器把立即数乘 2 省下大约一半的信号扇出和选择电路。代价落在生成和阅读编码的
  一方，也就是第 4 节里那样的拼接。
- 偏移都是 2 的倍数，所以 B 型的 13 位偏移只存 12 位，范围 -4096…+4094；J 型的 21 位偏移只存 20 位，
  范围 -1 MiB…+1 MiB-2（psABI:653、:656）。偏移都相对这条指令自己的地址（`rv32.adoc:433`、:561）。
- jalr 是 I 型，它的 12 位立即数是以字节为单位的普通偏移，不乘 2（`rv32.adoc:486` 起）。

## 6. LLVM 里的对应

- 指令定义里写明每一位来自哪里。`RISCV/RISCVInstrFormats.td:489–495` 的 RVInstB：
  ```
  let Inst{31}    = imm12{11};
  let Inst{30-25} = imm12{9-4};
  let Inst{11-8}  = imm12{3-0};
  let Inst{7}     = imm12{10};
  ```
  这里的 imm12 是偏移除以 2 之后的 12 位，所以 imm12{11} 就是偏移的 imm[12]，imm12{10} 就是 imm[11]。
  J 型在 :516–519。TableGen 从这些描述生成编码和反汇编用的 C++ 代码。
- 汇编时目标地址往往还不知道，例如跳到后面才出现的标签，或者别的文件里的函数。汇编器先在立即数
  的位置填 0，记一条 fixup：「这里的这几位，等知道了某个值，按某种规则填进去」。值在同一个文件里
  就能确定的，汇编器在文件末尾自己填；要等链接才知道的，变成目标文件里的重定位，交给链接器填。
  填 J 型立即数时拆位的代码在 `RISCV/MCTargetDesc/RISCVAsmBackend.cpp:502` 起，B 型在 :520 起。
